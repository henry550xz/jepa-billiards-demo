THE HYPOTHESIS

A useful code near 2 × balls × spatial dimensions might support accurate forecasts with a small predictor.

Environment → image history → latent state → dynamics

Here: 2 balls × 3 dimensions × position/velocity = 12 state coordinates. State dimension is a reference, not a guarantee of an easy learned transition.

01 / the controlled world

Fix the environment. Vary the code and the predictor.

Environment complexity

Two colored balls move in a unit 3D box, with wall reflections and ball collisions. The model sees three RGB frames containing XY, XZ and YZ views. Positions and velocities define a 12-coordinate physical state.

Representation capacity

The same image-encoder architecture produces a history code of size 6, 12, 24 or 48: half, equal to, twice or four times the physical-state dimension. Representation learning receives images, not state labels.

Predictor capacity

Freeze each learned encoder and fit three transitions on the same codes: affine, one-hidden-layer MLP-64 and MLP-256. Encode the initial history once, then predict without future images for 1.28 seconds.

We trained every encoder for 20,000 updates with a common MLP-256 training predictor, then fitted each frozen-feature predictor for 10,000 updates. The completed primary sweep contains all four latent sizes × three predictors × three training seeds: 36 predictor fits evaluated on 256 held-out episodes.

The main sweep uses Gaussian-regularized codes; representation-family comparisons are a secondary robustness check. The experiment tests predictor complexity conditional on already learned codes, rather than joint learning with each small predictor.

How environment complexity relates to the two capacities

State size: with n balls in d spatial dimensions, positions and velocities require 2nd coordinates. This describes the simulator state; a learned image code is not assumed to recover those coordinates.

Transition complexity: free motion is simple, but wall and ball contacts introduce conditional changes in velocity. More balls introduce more possible interacting pairs. Even an adequately sized code need not make these transitions affine; its coordinate system also matters.

What we test here: latent size and predictor width within one fixed two-ball, 3D environment. We do not infer a scaling law across ball counts or dimensions from this sweep. A larger environment-complexity sweep would be a separate follow-up.

06 / findings in relation to the hypothesis
Matching state dimension does not automatically simplify learned dynamics.
A smaller code did not make forecasting easier.
At L6, nonlinear predictors show much larger long-horizon errors than at L12 or L24. Increasing to L48 does not consistently help. The tested sweep shows no monotonic rule that a smaller or larger latent makes prediction easier.
A simple predictor stays bounded, but accuracy matters.
Affine position RMSE stays near 0.214 across all four latent sizes. Actual-future-image readout error is also about 0.21. These nearly equal errors do not establish that a six- or twelve-dimensional code is a useful sufficient state.
A more complex predictor fits locally, yet can roll out poorly.
At L12, MLP-64 and MLP-256 reduce one-step feature MSE dramatically relative to affine, but several seeds accumulate large forecast errors. More capacity improves local fit without guaranteeing stable physical dynamics.
What this says about the hypothesis: a physical-state-sized bottleneck plus a higher-capacity transition is not sufficient by itself in these fixed-budget runs. Code size, recoverable state information and rollout stability must be assessed together. We have not identified a minimum sufficient latent size or a required predictor width.
The 12-coordinate state is a dimensional reference, not a claim that the learned code uses physical coordinates. True-state learned controls also have limited long-horizon position gains, so the encoder bottleneck alone is not isolated as the cause. Position and velocity results must be read separately.
